# Operations

Use `rumi_frontend_design_pack` when the requested work fits its owner surfaces: frontend_briefs, design_system_fit, responsive_visual_qa, component_acceptance_criteria. Start by collecting enough evidence, then route any overlapping execution to the owner pack named in setup metadata. Do not treat a generated plan as completed work until the relevant evidence proves the requested outcome.

## Review Steps

1. Classify the request with `catalog/frontend_workflows.yaml`.
2. Apply `catalog/design_system_fit_rubric.yaml` before handing off implementation.
3. Use `catalog/responsive_qa_matrix.yaml` to name the required viewport evidence.
4. Complete `checklists/component_acceptance.checklist.yaml` for component briefs.
5. Route code edits, browser screenshots, and media provenance to their owner packs.
