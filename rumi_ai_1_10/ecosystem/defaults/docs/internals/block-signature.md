# Block signature specification

All blocks in the defaults pack are placed in `blocks/<category>/<name>.py` and follow a uniform signature.

---

## Rules for `def run(input_data, context)`

Every block exports a `run` function with the following signature at the module level:

```python
def run(input_data: dict, context: dict) -> dict:
```

### Structure of input_data

`input_data` is a dict that stores request data from clients. Passed after the transport layer does the following:

In the case of HTTP, the dict that is the parsed JSON Body is passed as is. The path parameter is pre-injected into `input_data` by the transport layer. For example, for `/api/chat/conversations/{id}`:

```python
input_data["conversation_id"] = path_params.get("id", "")
```

In the case of stdio/UDS, the contents of the `"data"` field of the request JSON is passed. Injection of path parameters is done automatically based on `_ID_INJECT_MAP`.

The fields included in `input_data` differ depending on each block. Each block obtains the fields it needs using `input_data.get()`, and returns `error()` if it is insufficient.

### All fields of context

#### transport Fields when calling directly

Base field generated by `_build_context()` for each transport. Must be present on every call.

| Field | Type | Description |
|---|---|---|
| `flow_id` | `string` | Execution flow identifier. transport When calling directly, either `"transport_direct"` (HTTP), `"stdio_direct"` (stdio), or `"uds_direct"` (UDS) |
| `step_id` | `string` | Identifier of the step. transport When calling directly, either `"http_request"` (HTTP), `"stdio_request"` (stdio), or `"uds_request"` (UDS) |
| `phase` | `string` | always `"execute"` |
| `ts` | `string` | ISO 8601 timestamp (e.g. `"2025-01-01T00:00:00Z"`) |
| `owner_pack` | `string` | always `"defaults"` |
| `inputs` | `dict` | Additional input. Usually empty dict |

#### Fields added via Flow engine/kernel

When handler is called via the Flow engine or via `call_handler`, the kernel injects the following additional fields into context: These fields do not exist when calling transport directly (the handler must safely retrieve them using `context.get()`).

| Field | Type | Description |
|---|---|---|
| `call_handler` | `callable \| None` | Function that calls other handlers. Signature of `call_handler(handler_name: str, input_data: dict) -> dict`. Resolve the handler name through the kernel's InterfaceRegistry and call the target `run()` |
| `emit_event` | `callable \| None` | Function that fires an event. Signature of `emit_event(event_type: str, data: dict) -> None`. Send events to the kernel's EventBus |
| `wait_event` | `callable \| None` | Function that waits for an event. Signature of `wait_event(event_type: str, timeout: int, filter: dict) -> dict \| None`. Block until the specified event fires |
| `emit_widget` | `callable \| None` | Function that sends the Widget to the UI. Signature of `emit_widget(widget_json: dict) -> None`. Send the Widget structure defined in `lib/rumi_widgets/` |
| `cancel_check` | `callable \| None` | Function to check if the current execution has been canceled. Signature of `cancel_check() -> bool`. Call it periodically in a long-running loop and use it for early termination |
| `handler_config` | `dict \| None` | Handler configuration information. Handler-specific settings defined in `conditions.json` etc. are injected from the kernel |
| `session` | `dict \| None` | Session information. Contains fields such as `session_id`, `workspace`. Used for session scope state management |

#### Examples of using the context field

```python
def run(input_data, context):
    # transport 直接呼び出し時のベースフィールド（常に存在）
    flow_id = context["flow_id"]
    ts = context["ts"]

    # Flow エンジン経由のフィールド（存在しない場合がある）
    call_handler = context.get("call_handler")
    emit_event = context.get("emit_event")
    emit_widget = context.get("emit_widget")
    cancel_check = context.get("cancel_check")
    session = context.get("session")
    handler_config = context.get("handler_config")

    # call_handler が存在する場合のみ他の handler を呼び出す
    if call_handler is not None:
        result = call_handler("defaults.ai.complete", {
            "model": "openai/gpt-4o",
            "messages": [{"role": "user", "content": "Hello"}],
        })

    # cancel_check が存在する場合のみキャンセルチェック
    if cancel_check is not None and cancel_check():
        return error("execution cancelled", "CANCELLED")

    return ok({"done": True})
```

## Return value — `ok()` / `error()` format

All blocks return results using `blocks/_common.py`, `ok()` or `error()`.

### Successful response

```python
from blocks._common import ok

return ok({"key": "value"})
# → {"status": "ok", "data": {"key": "value"}}

return ok(None)
# → {"status": "ok", "data": null}
```

### Error response

```python
from blocks._common import error

return error("conversation_id is required", "INVALID_INPUT")
# → {"status": "error", "error": {"code": "INVALID_INPUT", "message": "conversation_id is required"}}

return error("something went wrong")
# → {"status": "error", "error": {"code": "ERROR", "message": "something went wrong"}}
```

### Unimplemented stub

```python
from blocks._common import not_implemented

return not_implemented("defaults.some.handler")
# → {"status": "ok", "data": null, "_stub": true, "_handler": "defaults.some.handler"}
```

### Static files (only for transport/http.py)

Only the HTTP transport has a special format for returning static files:

```python
return {"_static": True, "content_type": "text/html; charset=utf-8", "body": "<html>...</html>"}
```

## import path rules

All block files set `sys.path` at the beginning with the following pattern:

```python
import sys
import os
sys.path.insert(0, os.path.join(os.path.dirname(__file__), "..", ".."))
```

This allows you to import with an absolute path from the pack root:

```python
from blocks._common import ok, error, gen_id, timestamp
from domain.chat.store import ChatStore
from domain.ai_client.client import AIClient
```

`sys.path.insert(0, ...)` should be written at the beginning of the file (before other imports).

## All functions of `_common.py`

`blocks/_common.py` provides the following five functions:

### `ok(data=None) -> dict`

Return a success response. Pass any JSON serializable object to `data`.

```python
ok({"id": "abc"})   # → {"status": "ok", "data": {"id": "abc"}}
ok()                 # → {"status": "ok", "data": null}
```

### `error(message, code="ERROR") -> dict`

Returns an error response.

```python
error("not found", "NOT_FOUND")  # → {"status": "error", "error": {"code": "NOT_FOUND", "message": "not found"}}
error("fail")                     # → {"status": "error", "error": {"code": "ERROR", "message": "fail"}}
```

### `not_implemented(handler_name) -> dict`

Returns a stub response for an unimplemented handler.

```python
not_implemented("defaults.foo.bar")
# → {"status": "ok", "data": null, "_stub": true, "_handler": "defaults.foo.bar"}
```

### `timestamp() -> str`

Returns a UTC timestamp string in ISO 8601 format.

```python
timestamp()  # → "2025-01-01T00:00:00Z"
```

Internal implementation: `time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime())`

### `gen_id() -> str`

Returns a UUID v4 string.

```python
gen_id()  # → "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
```

Internal implementation: `str(uuid.uuid4())`
