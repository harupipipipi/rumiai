# 외부 토큰

외부 입력 공급자는 확인 및 아웃바운드 응답을 위해 암호가 필요합니다.
Rumi는 이러한 값을 쓰기 전용 자격 증명으로 처리합니다.

원시 토큰 값은 UI, API 응답, 로그, 감사 기록에 표시되어서는 안 됩니다.
디버그 덤프, 생성된 문서 또는 배달 상태.

## 토큰 클래스

| 수업 | 예 | 사용 |
|---|---|---|
| 서명 비밀 | Slack 서명 비밀, LINE 채널 비밀 | 인바운드 웹훅 확인 |
| 공개인증키 | Discord 공개 키 | 인바운드 상호작용 확인 |
| 아웃바운드 봇 토큰 | Slack 봇 토큰, Discord 봇 토큰, LINE 채널 액세스 토큰 | 답장 보내기 |
| 웹훅 URL | Discord 웹훅 URL 또는 일반 콜백 비밀 | 공급자별 웹훅 메시지 보내기 |
| 지역 섭취 토큰 | 게이트웨이 전달자 토큰 또는 웹훅 공유 토큰 | 현지 섭취량 보호 |
| 응답 핸들 | LINE 응답 토큰, Discord 상호작용 ID/토큰 | 단기 응답 보내기 |

회신 핸들은 수명이 긴 자격 증명은 아니지만 여전히 다음과 같이 처리되어야 합니다.
응답을 승인할 수 있기 때문에 민감합니다.

## 저장

외부 공급자 자격 증명은 Rumi 비밀 저장소 또는 프로세스에 있어야 합니다.
환경. 코드와 프로필은 원시 값이 아닌 비밀 이름을 참조해야 합니다.

명명된 외부 토큰 API는 공급자 API 키와 동일한 패턴을 따릅니다.

| 엔드포인트 | 행동 |
|---|---|
| §루미§0§ | 공급자 토큰 상태, 마스킹된 레이블, 종류 및 엔드포인트 링크를 반환합니다. |
| §루미§0§ | `upsert`, `rename`, 또는 `delete` 명명된 토큰 |

명명된 토큰 비밀 키는 `RUMIEXT_{PROVIDER}_{TOKEN_ID}`을 사용합니다. 메타데이터가 저장됩니다
원시 비밀과 별도로 공급자 ID, 토큰 ID, 표시 이름,
종류, 범위, 엔드포인트 ID, 타임스탬프.

기존 통합 비밀 API는 호환성을 위해 그대로 유지됩니다.

| 엔드포인트 | 행동 |
|---|---|
| §루미§0§ | 공급자 상태 및 구성된 키 이름만 반환 |
| §루미§0§ | 지원되는 비밀 값을 설정하거나 지웁니다 |

쓰기 엔드포인트는 저장을 위한 유입 경로이므로 원시 값을 허용합니다.
비밀. 응답은 해당 값을 반영해서는 안 됩니다.

## 표시 규칙

허용됨:

```json
{
  "provider_id": "slack",
  "configured": true,
  "configured_keys": ["SLACK_SIGNING_SECRET", "SLACK_BOT_TOKEN"]
}
```

허용되지 않음:

```json
{
  "SLACK_BOT_TOKEN": "<raw-token-value>"
}
```

구체적인 내용이 없는 한 접두사나 접미사를 표시하여 부분적으로 마스크하지 마세요.
운영자가 필요하며 해당 값을 자격 증명으로 사용할 수 없습니다. 안정적인 키를 선호합니다
이름, 해시, 생성 시간 및 순환 상태.

## 감사 및 수정

감사 기록에는 다음이 포함될 수 있습니다.

- 비밀 이름;
- 제공자 ID
- 배우;
- 작동: 설정, 지우기, 회전, 확인;
- 성공 또는 실패;
- 오류 카테고리를 수정했습니다.

감사 기록에는 다음이 포함되어서는 안 됩니다.

- 토큰 값
- 승인 헤더;
- 쿠키;
- 비밀 값에 서명합니다.
- 응답 토큰 값
- 자격 증명이 포함된 경우 전체 공급자 요청 본문입니다.

## 회전

프로필을 변경하지 않고도 회전이 지원되어야 합니다.

1. 동일한 비밀 이름으로 새 비밀을 저장합니다.
2. 수신 서명 또는 아웃바운드 전달을 확인합니다.
3. 이전 공급자 측 자격 증명을 제거합니다.
4. 수정된 감사 이벤트를 기록합니다.

프로필은 비밀을 참조하므로 순환 중에 편집할 필요가 없습니다.
비밀 값이 아닌 이름.

## URL 제공자는 토큰이 아닙니다

터널 또는 수신 URL은 자격 증명이 아닌 구성이지만 여전히 가능합니다.
민감한 운영 세부정보. Cloudflare Quick Tunnel은 가능한 URL 중 하나입니다.
개발 제공자. 외부 입력 프레임워크는 동일한 방식으로 작동해야 합니다.
터널, 역방향 프록시 또는 호스팅 수신이 가능합니다.
