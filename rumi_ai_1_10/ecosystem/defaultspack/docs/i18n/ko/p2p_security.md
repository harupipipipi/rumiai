# P2P 보안

P2P는 신뢰 경계나 경계가 아닌 선택적 수신 표면으로 처리됩니다.
도구 운송. 안전한 기본값은 P2P 수신기 없음, 피어 검색 없음 및 없음입니다.
인터넷 중계.

## 기본값

- P2P는 기본적으로 비활성화되어 있습니다.
- 로컬 HTTP/런타임 제어 평면은 기본적으로 루프백에 바인딩됩니다.
  (§루미§0§/§루미§1§/§루미§2§).
- LAN 검색, 멀티캐스트, mDNS, DHT, STUN/TURN 릴레이 또는 호스팅이 없습니다.
  defaultspack의 인터넷 릴레이.
- 향후 피어 섭취를 활성화하려면 명시적인 로컬 구성이 필요하며 반드시
  민감한 경로에 사용되는 것과 동일한 로컬 관리자 경로 보호를 유지합니다.

## 수신 경계

피어 메시지는 외부 입력 이벤트와 동일합니다.

```text
peer payload
  -> normalized external event
  -> audience/input policy
  -> chat or agent message
  -> normal response/tool planning
```

피어는 사용자에게 표시되는 입력을 추가할 수 있습니다. 도구를 직접 실행할 수는 없습니다.
핸들러, 파일 쓰기, 터미널 명령 실행, Git 푸시, 팩 설치, 변경
설정을 수행하거나 로컬 승인 토큰을 생성하세요.

피어가 Rumi에게 민감한 작업을 수행하도록 요청하면 해당 요청은 채팅이 됩니다.
맥락. 그러면 로컬 런타임이 도구 호출을 제안할 수 있지만 실행은 계속됩니다.
로컬 정책, 위험 분류, 승인 토큰 바인딩을 거쳐
감사.

## 승인 규칙

- 원격 피어는 로컬 작업을 승인할 수 없습니다.
- 승인 토큰은 로컬에서 일회성으로 서명되고 작업 플러스에 바인딩됩니다.
  인수 해시.
- 경로, 명령, git 대상, 콘텐츠, 대상 또는 기타 변경
  승인 후 보호된 인수는 실행을 무효화합니다.
- 로컬 사용자의 정책 결정은 피어 메타데이터, 피어 ID 및
  모델 출력.

## 데이터 처리

피어 식별자와 페이로드 메타데이터는 수정 후에만 기록되어야 합니다.
비밀, 전달자 토큰, 쿠키, API 키 및 공급자 자격 증명은 절대로
동료로부터 권위자로 받아들여진다. 자격 증명이 필요한 경우 Rumi는
기존 로컬 비밀 및 승인 흐름을 통해 로컬 사용자.

## 비골

P2P는 원격 데스크톱 프로토콜, 분산 도구 버스, 원격 승인이 아닙니다.
시스템, LAN 서비스 검색 기능 또는 공급자별 대체 기능
웹훅 확인.
