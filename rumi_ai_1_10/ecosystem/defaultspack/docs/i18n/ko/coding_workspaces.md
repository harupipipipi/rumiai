# 코딩 작업공간

코딩 작업공간은 로컬 파일, 터미널 및
자식 일. 에이전트는 모든 항목을 유지하면서 프로젝트 파일을 검사하고 변경할 수 있습니다.
구성된 하나의 작업 공간을 기반으로 하는 작업입니다.

## 루트 해결

작업공간 루트는 명시적 입력, 런타임 컨텍스트,
`RUMI_DEFAULTSPACK_WORKSPACE_ROOT` 또는 기본 사용자 데이터 작업 공간입니다. 는
해결된 루트는 필요할 때 생성되고 경로에 대한 권한으로 처리됩니다.
수표.

모든 파일 경로는 해당 루트에 대해 정규화됩니다.

- 상대 경로는 루트 아래에 결합됩니다.
- 절대 경로는 루트 내부에서 확인되는 경우에만 허용됩니다.
- 루트 외부의 경로 순회는 거부됩니다.
- 반환된 경로는 가능한 경우 작업공간 기준이어야 합니다.

## 파일 규칙

`FileOps`은 읽기, 쓰기, 생성, 삭제, 이동, 차이점에 대해 루트 제한을 적용합니다.
패치, 스냅샷, 복원. 텍스트 읽기는 바이너리 파일 및 크기가 큰 텍스트를 거부합니다.
입력. `.git` 및 `.git`와 같은 보호된 작업 공간 내부의 돌연변이
`.rumi_snapshots`이 차단되었습니다.

쓰기와 유사한 작업은 미리 볼 수 있고 승인을 인식해야 합니다. 파괴적인
삭제 및 복원 경로는 스냅샷을 사용하므로 정책이 적용되는 경우에도 복구가 가능합니다.
행동을 허용합니다.

## 터미널 규칙

터미널 명령은 작업 공간 루트에 제한된 `cwd`으로 실행됩니다. 터미널
분류자는 쉘 구문, 설치 프로그램, 네트워크 유틸리티, 권한 변경을 표시합니다.
승인이 필요한 파괴적인 명령. 작은 허용 목록만
환경 변수가 전달되며 `RUMI_` 변수가 명시적으로 허용됩니다.
런타임 통합을 위해.

P2P 또는 외부 입력은 터미널 명령을 직접 실행할 수 없습니다. 그것은 단지
로컬 에이전트가 로컬을 통해 계획, 분류 및 보낼 수 있는 요청을 생성합니다.
승인.

## Git 규칙

Git 작업은 작업공간 루트에서 실행되고 검색된 Git
최상위 디렉토리도 작업공간 루트 내에 있어야 합니다. 상태와 차이점은 다음과 같습니다.
읽기 작업; 커밋과 푸시는 여전히 민감하며 로컬 승인이 필요합니다.
정책이 요구할 때 경로를 선택합니다.

## 능력 그래프

`defaultspack.coding_workspace`은 시작을 묶는 최소 그래프 모양이고,
AI 클라이언트, 도구, 에이전트, CLI 표면 및 프런트엔드 표면. 그래프 컴파일
작업 공간 제한을 완화하지 않습니다. 런타임 프로필만 어셈블합니다.
동일한 제한된 핸들러를 사용합니다.
