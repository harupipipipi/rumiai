# 컴팩트

Compact는 장황한 내용을 대체하거나 보완하여 장기 실행 작업을 계속 사용할 수 있도록 합니다.
작은 연속 패킷과 요약이 포함된 기록. 컴팩트 패킷은
로컬 데이터를 보존해야 하며 작업 재개에 필요한 정보를 보존해야 합니다. 목표,
현재 상태, 진행 상황, 결정, 제약 조건, 변경된 파일, 도구 및
터미널 결과, 고정된 컨텍스트, 삭제된 컨텍스트 메모, 메모리 플러시 참조, 다음
단계 및 중요한 컨텍스트.

## 모드

- 제안: 기록을 분석하고 압축 가능한 세그먼트 계획을 반환합니다. 이것은
  기본적으로 비파괴적입니다.
- 적용: 선택한 메시지 범위를 요약 메시지로 바꿉니다. 이는 돌연변이를 일으킨다
  채팅 기록은 명시적이어야 합니다.
- 패킷: 내구성을 위해 로컬 defaultspack 사용자 데이터 아래에 압축 패킷을 작성합니다.
  재개 및 에이전트 런타임 핸드오프.
- 복원: 안전한 ID로 컴팩트 패킷을 읽고 컨텍스트를 재수화합니다.

## 비파괴적 기본값

자동 압축 제안은 기본적으로 계획 전용 동작으로 설정되어야 합니다. 다음을 사용할 수 있습니다.
장황하거나 대체된 세그먼트를 식별하는 모델이지만 실패는 안전하게 대체됩니다.
빈 계획에. 메시지를 삭제하거나 스크립트 범위를 바꾸거나
호출자가 명시적으로 적용 경로를 요청하지 않는 한 소스 컨텍스트를 삭제합니다.

압축이 적용되면 대체 메시지는 다음과 같은 메타데이터를 기록해야 합니다.
요약 상태, 편집 유형, 원본 메시지 수, 원본 메시지 ID 및
이유나 지시. 이렇게 하면 편집 내용을 감사 및 되돌릴 수 있게 유지됩니다.
역사층.

## 보존해야 할 것

압축하지 마세요:

- 원래 사용자 목표
- 최종 결과, 결정, 승인 또는 거부
- 최근 활성 컨텍스트
- 원시 형식의 자격 증명 또는 비밀
- 계속하려면 파일 경로, 명령, 오류 및 유효성 검사 결과가 필요합니다.
- 작업 공간 루트 제한 및 로컬 승인과 같은 정책 제약
  요구 사항.

## 보안 불변성

- 컴팩트는 승인 메커니즘이 아닙니다. 요약에서는 다음에 대한 권한을 부여할 수 없습니다.
  도구 호출.
- 로컬 정책, 승인 토큰, 작업 공간 제한 및 감사는 그대로 유지됩니다.
  압축 후 권위가 있습니다.
- P2P 또는 외부 입력은 다음을 통해서만 압축 요청을 트리거할 수 있습니다.
  정상적인 메시지 수신; 파괴적인 기록 편집을 강제할 수는 없습니다.
- 컴팩트 패킷은 로컬 아티팩트입니다. 모델이 이를 요약하는 데 도움이 된다면,
  결정적 대체는 클라우드 액세스 없이도 계속 작동해야 합니다.
