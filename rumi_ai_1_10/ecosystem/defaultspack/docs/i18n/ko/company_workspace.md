# 회사 업무공간

Company Workspace는 장기적으로 구축된 회사 스타일의 에이전트 형태를 설명합니다.
defaultspack 프리미티브 위에. 제품별 운영 회사
프로필은 `ecosystem/rumi_operations_company_pack/`에 있습니다. defaultspack이 소유하고 있습니다.
사용하는 일반 계약: 채팅 저장소, 에이전트 런타임, 스케줄러, 메모리,
컴팩트 컨텍스트, 도구 정책, 승인, 감사 및 작업 공간 범위 코딩.

작업 공간은 내부 회사 역할과 사용자가 대면하는 하나의 대화입니다.
그것. 클라이언트 관리자는 외부 스레드를 일관되게 유지하고 프로젝트 관리자는
코딩 엔지니어, 연구 전문가, 검토자, 운영 모니터 및
스케줄러 역할은 내부 상태와 채널을 통해 조정됩니다.

## 런타임 형태

- 회사 프로필은 선택 사항이며 defaultspack 시작이 아닌 팩 소유입니다.
  요구 사항.
- 부트스트랩은 하나의 조직, 하나의 운영 대화 및
  논스톱 모드가 요청될 때 간격 하트비트 일정.
- 역할은 기본적으로 최소 권한입니다. 각 역할에는 필요한 도구만 제공됩니다.
  그 일을 위해.
- 모델 자체 선택은 허용 목록 기반이며 감사를 기반으로 합니다.
- 장기 실행 메모리는 결정, 사건, 핸드오프, 간결한 요약,
  무제한 성적표 증가에 대한 상태를 예약합니다.

## 보안 불변성

- 지역 정책은 권위가 있습니다. 회사 역할은 defaultspack 도구를 우회할 수 없습니다.
  정책, 승인 게이트, 경로 가드 또는 감사.
- 파일 쓰기, 파괴적인 파일 작업, 터미널 실행, git 커밋/푸시,
  외부 전송, 설정 변경 및 자격 증명에는 여전히 일반 인증이 필요합니다.
  정책에 따라 민감하다고 표시되는 경우 로컬 승인 경로.
- 원격 피어 및 외부 시스템은 정규화된 방식을 통해서만 메시지를 제출할 수 있습니다.
  입력 경로. 승인을 부여하거나, 팩을 설치하거나, 설정을 변경하거나,
  로컬 승인 토큰을 발행합니다.
- 코딩 작업은 활성 작업공간 루트에만 국한됩니다. 회사의 역할은 다음과 같습니다.
  코드 변경을 요청하지만 파일, 터미널 및 Git 핸들러는 작업 공간을 적용합니다.
  경계.
- P2P는 향후 팩 또는 로컬 설정으로 활성화된 경우 메시지 수신 전용입니다. 그것
  도구 실행이나 승인 권한을 노출하지 않습니다. 참조
  §루미§0§.

## 운영 지침

지속적인 모니터링, 예정된 작업 및 작업을 위해 회사 작업 공간을 사용하십시오.
사용자가 여전히 하나의 명확한 클라이언트 지향 스레드를 원하는 다중 역할 실행.
정상적인 상태를 묵묵히 유지하고, 증거를 가지고 사건을 에스컬레이션하고, 요약합니다.
사용자에게 권한, 자격 증명 또는 판단을 요청하기 전에 내부 진행 상황.
