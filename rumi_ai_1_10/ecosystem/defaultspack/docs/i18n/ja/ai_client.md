# AI クライアントの設計

defaultspack AI クライアントは、フローとモデル プロバイダーの間の境界になります。それ
モデルの選択、プロバイダーの資格情報、リクエストの構築を正規化します。
ストリーミング イベントとプロバイダーの応答。プロンプト、ツール、メモリを所有していません。
または UI の動作。これらは、呼び出しフローとプロファイル ワークスペースによって提供されます。

## 責任

- 要求されたモデル プロファイルをプロバイダー、モデル ID、機能メタデータに解決します。
  そしてランタイム設定。
- 正規化されたメッセージ、ツール スキーマ、添付ファイルからプロバイダー リクエストを構築します。
  およびパラメータは上流のブロックによって提供されます。
- 呼び出しをプロバイダー アダプターにルーティングし、正規化された完了結果を返します。
- ストリーミング デルタを、チャットと UI レイヤーが使用できる安定したイベント名に正規化します。
  消費する。
- API キーを既存のプロバイダー キー ストアに保持します。モデルのプロフィールとドキュメントは次のとおりです。
  秘密を埋め込まないでください。

## 非責任

- プロンプトオーサリングとプロンプトミューテーションはプロンプト層に属します。
- ツールの検出、権限のフィルタリング、および承認の処理はツールに属し、
  AI リクエストが構築される前に権限がブロックされます。
- フロー オーケストレーションはフロー エンジンに属します。
- UI ウィジェットとアニメーションはモデル/プロファイル UI メタデータまたはフロントエンドに属します
  レンダラー。 AI クライアントはメタデータを渡すことができます。を定義すべきではありません
  製品体験。

## 契約のリクエスト

`defaults.ai.build_request` は、次のように消費される正規化されたリクエストを生成します。
`defaults.ai.complete`:

```json
{
  "conversation_id": "c1",
  "model": "stub/default",
  "messages": [
    {"role": "system", "content": "profile-scoped prompt"},
    {"role": "user", "content": "hello"}
  ],
  "tools": [],
  "params": {}
}
```

呼び出し元は、有効なシステム プロンプトを渡す責任があり、すでに
フィルタリングされたツール。 AI クライアントは、これらの入力を理由ではなくデータとして扱う必要があります。
プロンプト/ツール ストアの読み取りまたは変更を行います。

## モデルプロファイル

モデル プロファイルは、プロバイダー固有のモデルと機能を識別します。
ビジョン、ツールの呼び出し、思考のサポート、コンテキストの制限、およびルーティングのヒント。
入力が必要な場合、ルーティングは別のモデル プロファイルを推奨する場合があります。
選択したプロファイルに欠けている機能。プロバイダーキーはプロファイル外に残ります
書類。

## プロバイダーの検出

プロバイダーの検出はマニフェストファーストです。 OpenAI互換プロバイダーを追加可能
`extensions/llm/providers/<provider_id>/manifest.json` プラス付き
`models/*.json`;ランタイムはそこから `OpenAICompatibleProvider` をインスタンス化します。
資格情報が構成されるときにマニフェストを作成します。カスタム プロバイダー プロトコルは引き続き使用される可能性があります
明示的な Python エントリポイントを使用します。

厳選されたプロバイダーのメタデータはフォールバック互換性データです。レガシーを埋めるかもしれない
表示名またはデフォルトですが、マニフェストとモデル定義は正規のものです。
新しいプロバイダーのソース。

## ストリーミング イベント

プロバイダー固有のストリーミング チャンクは、チャット/UI に到達する前に正規化されます。
消費者。一般的なイベント名は次のとおりです。

- `message_start`
- `thinking_start`
- `thinking_delta`
- `thinking_end`
- `content_start`
- `content_delta`
- `tool_call_start`
- `tool_call_delta`
- `tool_call_end`
- `message_end`
- `error`

イベント ペイロードは、有用な場合にはメタデータの下にプロバイダーの詳細を保存する必要がありますが、
最上位のイベント名とテキスト/ツール フィールドはプロバイダー中立のままである必要があります。

## プロファイル UI メタデータ

モデル プロファイルが `ui/events.ui.yaml` などのオプションの UI メタデータを提供する場合、
ストリーミング層は、解決されたウィジェット ヒントを正規化されたイベント ペイロードに添付する場合があります。
これはパススルー契約です。

- ファイルはオプションです。
- 欠落しているメタデータは既存のストリーミング動作を保持する必要があります。
- テンプレートは現在のイベント データから解決される可能性があります。
- フロントエンド レンダラは、ウィジェット ヒントを使用するか無視するかを決定します。

AI クライアントは、「Thinking...」などのハードコードされたアニメーションをプロバイダーとして提供してはなりません
ロジック。プロファイルはそれらのヒントを説明できます。 AI クライアントはそれらを運ぶだけです。

## 失敗時の動作

プロバイダー エラーは、次のような構造化されたエラー結果に正規化する必要があります。
プロバイダー ID、モデル/プロファイル ID、既知の場合の再試行可能性、およびユーザーセーフ
メッセージ。資格情報が欠落している場合は、ネットワーク呼び出しの前にフェールクローズする必要があります。サポートされていません
機能はサイレントに削除するのではなく、機能エラーとして報告する必要があります。
ツール、画像、または思考パラメーター。
