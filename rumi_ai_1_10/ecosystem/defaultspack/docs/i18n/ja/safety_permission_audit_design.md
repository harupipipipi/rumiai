# 安全許可監査の設計

安全プリミティブ:

- 権限カタログ
- 許可、要求、拒否ポリシー
- リスク分類
- 承認ゲート
- ワークスペースルートの強制
- デフォルトでネットワーク拒否
- 秘密の編集
- 監査ログ

監査レコードには、タイムスタンプ、アクター、機能、操作、リスク レベル、決定、および編集された引数が含まれます。シークレット値は監査レコードに書き込まれることはありません。

## ローカルガードを実装しました

defaultspack は、ローカル コーディング ルートを機密性の高い HTTP 操作として扱うようになりました。の
ガードはローカル操作の保護であり、ユーザー認証ではありません。

HTTP トランスポートは、ループバック クライアント、ローカル オリジン、CSRF メタデータをチェックします。
Origin ヘッダーを含む機密性の高い突然変異とルートごとの機密性。
次に、コーディング ブロックは書き込みを実行する前に署名された承認トークンを検証します。
破壊的なファイル操作、ターミナルの中/高リスク実行、git commit、または
gitプッシュ。

承認トークンは、ローカルのランタイム シークレットを使用して HMAC 署名されています。各トークンはバインドされています
に:

- 操作名。
- 承認された引数の安定したハッシュ。
- 承認リクエストID;
- 有効期限のタイムスタンプ。

トークンは 1 回限りの使用です。 UI または呼び出し元がパス、コマンド、git を変更した場合
承認、実行後のターゲット、ファイルコンテンツ、またはその他の保護された引数
は拒否され、失敗が記録されます。

## 監査ストレージ

ローカル監査ストアは JSONL です。デフォルトでは以下に書き込まれます
`ecosystem/defaultspack/user_data/audit/local_actions.jsonl`;テストまたは埋め込み
ランタイムは、`RUMI_DEFAULTSPACK_AUDIT_PATH` でパスをオーバーライドできます。

監査層は以下を記録します。

- 試み;
- 承認の作成と決定。
- 実行;
- 否認。
- 失敗。

引数は永続化の前に編集されます。 `api_key`を含むキー、
`authorization`、`token`、`secret`、`password`、または `cookie` は、
ネストされた辞書やリストを含む墨消しマーカー。
