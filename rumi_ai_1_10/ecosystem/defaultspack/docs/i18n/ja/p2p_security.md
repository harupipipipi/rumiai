# P2Pセキュリティ

P2P は、信頼境界や境界ではなく、オプションの入力サーフェスとして扱われます。
工具の輸送。安全なデフォルトは、P2P リスナーなし、ピア検出なし、およびなしです。
インターネット中継。

## デフォルト

- P2P はデフォルトで無効になっています。
- ローカル HTTP/ランタイム コントロール プレーンはデフォルトでループバックにバインドされます
  (`127.0.0.1`/`localhost`/`::1`)。
- LAN ディスカバリ、マルチキャスト、mDNS、DHT、STUN/TURN リレー、またはホスト型はありません。
  デフォルトパックのインターネットリレー。
- 今後のピア取り込みを有効にする場合は、明示的なローカル構成にする必要があり、
  機密性の高いルートで使用されるものと同じローカル管理ルート ガードを保持します。

## 進入境界

ピア メッセージは外部入力イベントと同等です。

```text
peer payload
  -> normalized external event
  -> audience/input policy
  -> chat or agent message
  -> normal response/tool planning
```

ピアはユーザーに表示される入力を追加できます。ツールを直接実行することはできません。
ハンドラー、ファイルの書き込み、ターミナル コマンドの実行、git のプッシュ、パックのインストール、変更
設定を行うか、ローカル承認トークンを作成します。

ピアが Rumi に機密性の高いアクションの実行を要求した場合、その要求はチャットになります
コンテキスト。その後、ローカル ランタイムがツール呼び出しを提案する可能性がありますが、実行はまだ続行されません。
ローカルポリシー、リスク分類、承認トークンバインディングを通過し、
監査する。

## 承認ルール

- リモート ピアはローカル アクションを承認できません。
- 承認トークンはローカル、ワンタイム、署名され、オペレーション プラスにバインドされます。
  引数のハッシュ。
- パス、コマンド、git ターゲット、コンテンツ、宛先などの変更
  承認後の保護された引数は実行を無効にします。
- ローカル ユーザーのポリシー決定は、ピアのメタデータ、ピア ID、
  モデルの出力。

## データ処理

ピア識別子とペイロード メタデータは、編集後にのみログに記録する必要があります。
シークレット、ベアラー トークン、Cookie、API キー、プロバイダーの資格情報は決して使用しないでください。
ピアから権威として受け入れられます。資格情報が必要な場合、Rumi は次の者に尋ねる必要があります。
既存のローカル シークレットと承認フローを介してローカル ユーザーにアクセスします。

## 非目標

P2P は、リモート デスクトップ プロトコル、分散ツール バス、リモート承認ではありません。
システム、LAN サービス検出機能、またはプロバイダー固有の代替機能
Webhook の検証。
