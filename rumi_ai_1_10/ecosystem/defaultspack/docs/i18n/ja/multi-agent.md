# チームワークスペースランタイム

ユーザー向けの主な調整パスは、チーム ワークスペース ランタイムです。
内部的には、実装は依然として `CompanySlackRuntime` を中心としています。
`domain/company/message_router.py` で実装され、永続的な実行時状態が
`domain/company/runtime_store.py`。

ランタイムは Slack に似ています。

- チャネルとスレッドはメッセージを保持します
- エージェントに作業をルーティングすることに言及
- アクティブなエージェントの実行は、ランタイム命令としてメンションを受け取ります
- アイドル状態のエージェントは、`agent.delegate` を通じて委任されたチームタスクを受け取ります。
- 会社の互換性レコードとチームのスレッド/メッセージを接続するリンクを実行します。
  AgentEngine の実行
- 運用マネージャーのチェックマークは、オープン、失効、ブロック、および承認待ちを検査します
  仕事
- スクライブの概要は、ワークスペース、チャネル、スレッド、タスク、および実行スコープをカバーします

企業レイヤーはツールを実行しません。作成、ルーティング、監視を行います
AgentEngine が実行されるため、ポリシー、承認、モデル機能、実行時プロファイル、
ワークスペースの信頼の適用は、既存のエージェント/ツールのダウンストリームに残ります
ランタイム。

## 用語に関する注記

- `delegation` は、別のエージェントに作業を送信するための正規のアクション名です。
  実行時の用語では、これは `agent.delegate` にマップされます。
- `subagent` は、委任されたラベルの互換性またはレガシー ラベルとして読み取られる必要があります。
  独立したプライマリ ランタイム アーキテクチャとしてではなく、機能します。
- `company` は、コード パス、ID、および古いルートで依然として一般的です。ドキュメントで使用されているのは、
ユーザーに面する表面を説明する場合は、`team workspace`。

## 従来の互換性

`/api/agent/multi/*` は互換性ラッパーとしてのみ利用可能です。の
ラッパーは `CompanySlackRuntime` にポストし、`deprecation_warning` を返します。

`domain/agent/multi.py` はレガシーのみです。これはデフォルトのチームワークスペースではありません
ランタイム。
