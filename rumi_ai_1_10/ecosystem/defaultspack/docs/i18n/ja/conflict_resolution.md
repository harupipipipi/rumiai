# Rumi AI OS のデフォルトの競合解決

Rumi AI OS エコシステムが成長するにつれて、必然的に複数のパックが同様の機能を提供するようになります (例: `tool_search`、`file_editor`)。この文書では、`defaults` パックが名前の衝突、ユーザー設定、安全な機能のインポートを処理して安定性を保証し、悪意のあるハイジャックを防止する方法について詳しく説明します。

## 名前の衝突

インストールされている 2 つ以上のパックが同じ識別子を持つエンティティ (ツール、フロー、エージェント) を宣言する場合、システムはクラッシュすることなくそれを確実に解決する必要があります。

### 1. 優先順位の階層 (優先順位ルール)
コア エンジンは、次の厳密な優先順位に基づいて名前を解決します。
1. **ユーザーオーバーライド (`user_data/preferences.json`):** ユーザーが識別子を特定のパック (例: `"search_tool": "com.example.advanced_search"`) に明示的にマップした場合、そのユーザーが絶対に優先します。
2. **明示的なパック接頭辞:** パックは内部的に識別子を接頭辞にする必要がありますが、コンポーネントは短縮名で呼び出すことができます。競合が存在する場合、呼び出し元は完全修飾名を使用する必要があります (例: `rumi.tools.search` と `my_company.tools.search`)。
3. **インストールされたパックの優先順位:** `defaults` パックは、インストールされたパックを管理するための UI を提供します。ユーザーはグローバルな「パックの優先順位」を設定できます。パック A の優先度がパック B よりも高い場合、パック A のツールが優先されます。
4. **組み込みのデフォルト フォールバック:** 要求されたコンポーネントが見つからないか失敗した場合、コア システムは `defaults` パック実装にフォールバックします。

### 2. 曖昧さに対するユーザーのプロンプト
エージェントが `calculator` という名前のツールを呼び出そうとし、`pack_a` と `pack_b` の両方が明確な優先順位ルール セットを *なしで* 提供する場合、次のことが発生します。
* `defaults` パックは実行フローを一時停止します。
* UI モーダルがポップアップし、ユーザーに優先実装を選択してルールとして保存するよう求めます。
    * *プロンプト:* 「パック A とパック B はどちらも '計算機' を提供します。このリクエストにはどちらを使用するべきですか? または永続的に使用する必要がありますか?」

## インポート許可

Rumi AI OS は、Python ライブラリおよびその他のパックに依存しています。 「悪意を想定する」原則を遵守するには、パックの輸入を厳しく管理する必要があります。

### 1. サンドボックスの制限
パックは隔離された環境で実行されます。単純に `import os` や `require('fs')` ということはできません。

### 2. 輸入補助金としての機能
コア OS のドキュメントで説明されているように、機能のインポートまたはシステム リソースへのアクセスには Capability Grant が必要です。 `defaults` パックは、このリクエストの UI を管理します。
* **アクセスの要求:** パックが初めてインストールまたは実行されるとき、その `ecosystem.json` は必要な機能を宣言します (例: `rumi.fs.read`、`external.python.requests`)。
* **承認フロー:** `defaults` パックはユーザー承認ダイアログを処理します。ユーザーには、パックが「何を」したいのか、そして「なぜ」が正確に示されます。
    * 付与された場合、システムは直接コード実行権限ではなく、出力プロキシまたは特殊なソケットをプロビジョニングします。
    * 拒否された場合、パックは「フェールソフト」する必要があります。これは、包括的なアプリケーション (チャット フローなど) がクラッシュせずに続行され、おそらく警告メッセージが表示されることを意味します。

### 3. パックツーパックのインポート (依存関係の解決)
`pack_a` が `defaults` または `pack_b` の関数を使用したい場合は、依存関係解決メカニズムに従います。
* **承認:** ユーザーは、`pack_a` が `pack_b` のパブリック インターフェイスを呼び出すことを許可され、1 つのパックが他の悪意のあるアクションを目に見えずに調整できないようにすることを承認する必要があります。
