# Rumi AI OS 默认冲突解决

随着 Rumi AI OS 生态系统的发展，多个包将不可避免地提供类似的功能（例如，`tool_search`、`file_editor`）。本文档详细介绍了`defaults`包如何处理命名冲突、用户首选项和安全功能导入，以保证稳定性并防止恶意劫持。

## 命名冲突

当两个或多个已安装的包声明具有相同标识符的实体（工具、流程、代理）时，系统必须可靠地解析它而不会崩溃。

### 1. 偏好层次结构（优先级规则）
核心引擎根据以下严格优先级解析名称：
1. **用户覆盖（`user_data/preferences.json`）：**如果用户将标识符显式映射到特定包（例如，`"search_tool": "com.example.advanced_search"`），则绝对获胜。
2. **显式包前缀：** 包应在内部为其标识符添加前缀，但可以通过其短名称来调用组件。如果存在冲突，调用者必须使用完全限定名称（例如，`rumi.tools.search` 与 `my_company.tools.search`）。
3. **已安装包优先级：** `defaults` 包提供了用于管理已安装包的 UI。用户可以设置全局“打包优先顺序”。如果包 A 的优先级高于包 B，则包 A 的工具获胜。
4. **内置默认回退：** 如果请求的组件丢失或失败，核心系统将回退到`defaults`包实现。

### 2. 用户提示歧义
如果代理尝试调用名为`calculator`的工具，并且`pack_a`和`pack_b`都在*没有*明确的优先级规则集的情况下提供该工具，则会发生以下情况：
* `defaults` 包暂停执行流程。
* 弹出一个 UI 模式，要求用户选择首选实现并将其保存为规则。
    * *提示：*“包 A 和包 B 都提供‘计算器’。哪个应该用于此请求，或者永久使用？”

## 导入权限

Rumi AI OS 依赖于 Python 库和其他包。为了坚持“假设恶意”原则，必须严格控制包装进口。

### 1. 沙盒限制
包在隔离环境中运行。他们不能简单地宽松地`import os`或`require('fs')`。

### 2. 进口补助金的能力
正如核心操作系统文档中所述，导入功能或访问系统资源需要能力授予。 `defaults` 包管理此请求的 UI。
* **请求访问：** 首次安装或执行包时，其`ecosystem.json`声明所需的功能（例如，`rumi.fs.read`、`external.python.requests`）。
* **批准流程：** `defaults` 包处理用户批准对话框。用户会准确地了解该包想要做什么以及为什么。
    * 如果授予，系统会提供出口代理或专用套接字，而不是直接代码执行权限。
    * 如果被拒绝，包必须“软失败”，这意味着总体应用程序（如聊天流程）将继续运行而不会崩溃，可能会出现警告消息。

### 3. 包间导入（依赖解析）
如果`pack_a`想要使用`defaults`或`pack_b`中的函数，它遵循依赖解析机制。
* **批准：** 用户必须批准允许`pack_a`调用`pack_b`的公共接口，确保一个包无法无形地策划另一项恶意操作。
