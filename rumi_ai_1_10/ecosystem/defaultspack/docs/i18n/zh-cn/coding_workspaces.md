# 编码工作区

编码工作空间是本地文件、终端和
git 工作。他们让代理检查和更改项目文件，同时保留每个
操作植根于一个已配置的工作区。

## 根解析

工作空间根由显式输入、运行时上下文解析，
`RUMI_DEFAULTSPACK_WORKSPACE_ROOT`，或默认用户数据工作区。的
解析根在需要时创建，并被视为路径的权限
检查。

所有文件路径都针对该根进行规范化：

- 相对路径连接在根下；
- 仅当绝对路径在根内部解析时才允许使用；
- 拒绝根之外的路径遍历；
- 如果可能，返回的路径应与工作空间相关。

## 文件规则

`FileOps` 强制执行读、写、创建、删除、移动、比较的根限制，
补丁、快照和恢复。文本读取拒绝二进制文件和超大文本
输入。受保护工作空间内部的突变，例如`.git`和
`.rumi_snapshots` 被屏蔽。

类似写入的操作应该是可预览的和可批准的。破坏性的
删除和恢复路径使用快照，因此在策略执行时恢复仍然是可能的
允许该操作。

## 终端规则

终端命令运行时，`cwd` 仅限于工作区根目录。航站楼
分类器标记 shell 语法、安装程序、网络实用程序、权限更改、
和破坏性命令需要批准。只有一小部分许可名单
环境变量被转发，明确允许`RUMI_`变量
用于运行时集成。

P2P或外部输入不能直接执行终端命令。它只能
创建本地代理可以计划、分类并通过本地发送的请求
批准。

## Git 规则

Git操作从工作空间根执行，并且发现的git
顶级目录也必须位于工作区根目录内。状态和差异是
读操作； commit 和 Push 仍然敏感，需要当地批准
政策需要时的路径。

## 能力图

`defaultspack.coding_workspace`是绑定start的最小图形形状，
AI 客户端、工具、代理、CLI 界面和前端界面。编译图表
不放松任何工作空间限制；它只组装运行时配置文件
使用相同的受限处理程序。
