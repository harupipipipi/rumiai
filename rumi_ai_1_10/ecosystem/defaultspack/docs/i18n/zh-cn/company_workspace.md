# 公司工作区

公司工作区描述了长期运行的、公司风格的代理形态
在 defaultspack 原语之上。特定产品运营公司
个人资料位于`ecosystem/rumi_operations_company_pack/`；默认包拥有
它使用的通用合约：聊天存储、代理运行时、调度程序、内存、
紧凑的上下文、工具策略、批准、审计和工作区范围的编码。

工作空间是一种面向用户的对话，背后有公司内部角色
它。客户经理保持外部线程的连贯性，而项目经理，
编码工程师、研究专家、审稿人、运营监控员以及
调度程序角色通过内部状态和通道进行协调。

## 运行时形状

- 公司简介是可选的并且由 pack 拥有，而不是 defaultspack 启动
  要求。
- Bootstrap 创建或重用一个组织、一个操作对话，以及
  请求不间断模式时的间隔心跳计划。
- 默认情况下，角色具有最低权限。每个角色仅收到所需的工具
  为了它的工作。
- 模型自选基于许可名单并经过审核。
- 长时间运行的记忆更喜欢决策、事件、交接、紧凑的摘要，
  并在无限制的成绩单增长上安排状态。

## 安全不变量

——地方政策具有权威性。公司角色无法绕过defaultspack工具
  政策、审批门、路线守卫或审计。
- 文件写入、破坏性文件操作、终端执行、git commit/push、
  外部发送、设置突变和凭据仍然需要正常的
  当政策将其标记为敏感时，当地的批准路径。
- 远程对等点和外部系统只能通过规范化提交消息
  输入路径。他们无法授予批准、安装包、改变设置或
  发行本地批准令牌。
- 编码工作仍然局限于活动工作空间根目录。公司角色可能
  要求更改代码，但文件、终端和 git 处理程序强制执行工作空间
  边界。
- P2P（如果由未来的包或本地设置启用）仅是消息入口。它
  不公开工具执行或批准权限。参见
  §鲁米§0§。

## 操作指导

使用公司工作空间进行持续监控、安排工作和
多角色执行，用户仍然需要一个清晰的面向客户端的线程。
保持正常状态沉默，用证据升级事件并总结
在向用户询问权限、凭据或判断之前的内部进展。
