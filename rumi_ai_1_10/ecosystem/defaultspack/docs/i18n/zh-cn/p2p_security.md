# P2P 安全

P2P 被视为可选的入口表面，而不是信任边界，也不是
工具运输。安全的默认设置是没有 P2P 侦听器、没有对等点发现、并且没有
互联网中继。

## 默认值

- 默认情况下禁用 P2P。
- 本地HTTP/运行时控制平面默认绑定到环回
  （`127.0.0.1`/`localhost`/`::1`）。
- 没有 LAN 发现、多播、mDNS、DHT、STUN/TURN 中继或托管
  默认包中的互联网中继。
- 启用任何未来的对等接收必须是显式本地配置并且必须
  保留敏感路由使用的相同本地管理路由防护。

## 入口边界

对等消息相当于外部输入事件：

```text
peer payload
  -> normalized external event
  -> audience/input policy
  -> chat or agent message
  -> normal response/tool planning
```

对等方可以添加用户可见的输入。它不能直接执行工具，调用
处理程序、写入文件、运行终端命令、推送 git、安装包、更改
设置，或创建本地批准令牌。

如果同伴要求鲁米执行敏感操作，该请求就会变成聊天
上下文。然后，本地运行时可能会提出工具调用，但仍会执行
通过本地政策、风险分类、批准令牌绑定，以及
审计。

## 审批规则

- 远程对等方无法批准本地操作。
- 批准令牌是本地的、一次性的、签名的并且绑定到操作 plus
  参数哈希。
- 更改路径、命令、git 目标、内容、目的地或其他
  批准后受保护的参数使执行无效。
- 本地用户的策略决策胜过对等元数据、对等身份和
  模型输出。

## 数据处理

对等标识符和有效负载元数据应仅在编辑后记录。
秘密、不记名令牌、cookie、API 密钥和提供商凭证绝不能被泄露
从同行那里接受为权威。如果需要凭证，鲁米应该询问
本地用户通过现有的本地秘密和批准流程。

## 非目标

P2P不是远程桌面协议、分布式工具总线、远程审批
系统、LAN 服务发现功能或特定提供商的替代品
网络钩子验证。
