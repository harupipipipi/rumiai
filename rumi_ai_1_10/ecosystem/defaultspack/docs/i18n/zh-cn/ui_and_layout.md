# Rumi AI OS 默认 UI 和布局

本文档详细介绍了 `defaults` 包提供的 UI 组件的设计原则和期望，特别解决了自定义、拖放功能和动态工具显示的要求。

## 核心 UI 理念：通过资产实现灵活性

Rumi AI OS 前端不是一个单一的应用程序；它是包提供的“资产”的聚合。 `defaults`包设置了标准网格和交互模型，但几乎每个元素都是可替换的。

### 基于资产的 UI 注册表
1. **前后端分离：** 后端处理逻辑、流程执行和数据存储。前端专门负责渲染包注册的资源。
2. **资产目录：** 包在 `assets` 数组下的 `ecosystem.json` 中定义 UI 组件（例如自定义聊天窗口、新的输入样式或设置面板）。
3. **UI 设置包：** 可以安装概念或文字包（如`settings_pack`），它声明通用布局资源（例如，“全屏布局”、“侧边栏覆盖”）。 `defaults`包提供基线网格。

## 拖放架构

满足任意放置的需求（例如随意放置聊天窗口或输入框）：

1. **画布容器：** 主 UI 被视为“画布”。
2. **可拖动组件：** 默认包的核心输入和输出（聊天流、输入栏、工具状态）包含在可拖动资源容器中。
3. **位置持久性：** 当用户移动组件时，其新的`(x, y)`或`grid-area`坐标将保存到用户的`user_data`目录中的`ui_preferences.json`中。 `defaults` 包在重新加载时遵循这些坐标。

## 动态工具显示和设置

工具必须告知用户人工智能当前正在做什么。

### 1. 工具侧边栏（活动日志）
* **用途：** `defaults` 包包含标准侧边栏活动日志。
* **注册：** 当 AI 代理执行工具（通过 Flow Engine）时，后端会发出 UI 事件。侧边栏侦听这些事件并显示实时执行状态（例如，“在网络上搜索‘Python 库’...”、“阅读`config.yaml`...”）。
* **可见性：** 这允许用户了解人工智能的当前上下文，而不会扰乱主要对话流。

### 2.自定义工具显示（ToolDisplay Assets）
有些工具需要的不仅仅是文本日志（例如数据可视化工具、图像生成器）。
* **`tooldisplay` 注册：** 工具包可以注册标记为`type: tooldisplay` 的特定前端资产（React 组件或 Web 组件）。
* **动态注入：** 执行该工具时，`defaults` 包的 UI 编排器会将此自定义资源动态注入到活动工具区域（通常是模态或专用拆分窗格）。

### 3. 工具设置（ToolSetting Assets）
用户需要配置工具（例如，输入 API 密钥、设置搜索首选项）。
* **`toolsetting` 注册：** 工具包为其设置提供 JSON 架构或自定义 UI 资产。
* **自动 UI 生成：** 默认情况下，如果仅提供架构，`defaults` 包会根据架构类型自动生成设置表单（输入、切换）。如果提供了自定义资源，则会渲染该资源。这可以通过“工具”类别下的主设置面板进行访问。

## 动画标准化

为了防止不同包之间的视觉冲突：

1. **动画常量：** `defaults` 包定义了用于过渡的标准 CSS 变量（例如，`--rumi-anim-fast: 150ms ease`、`--rumi-anim-medium: 300ms ease-in-out`）。
2. **指南：** 通过文档强烈鼓励包开发人员将这些变量用于工具显示和自定义 UI 资产，以保持一致的体验。

## 后备机制

如果自定义 UI 资源无法加载或引发错误：
1. **失败软渲染：** `defaults` 包将捕获错误，从屏幕上删除有问题的组件，并渲染一个简单的错误边界块，确保操作系统的其余部分（如核心聊天）保持功能。
