# 人工智能客户端设计

defaultspack AI 客户端是流程和模型提供者之间的边界。它
标准化模型选择、提供商凭证、请求构建，
流事件和提供商响应。它不拥有提示、工具、内存、
或用户界面行为；这些由调用流程和配置文件工作区提供。

## 职责

- 将请求的模型配置文件解析为提供商、模型 ID、功能元数据、
  和运行时设置。
- 根据标准化消息、工具模式、附件构建提供商请求
  以及上游块提供的参数。
- 将调用路由到提供者适配器并返回规范化的完成结果。
- 将流增量标准化为聊天和 UI 层可以使用的稳定事件名称
  消耗。
- 将 API 密钥保存在现有的提供商密钥存储中。模型配置文件和文档必须
  不嵌入秘密。

## 非责任

- 提示创作和提示变异属于提示层。
- 工具发现、权限过滤、审批处理属于工具，
  在构建 AI 请求之前进行权限阻止。
- 流程编排属于流程引擎。
- UI 小部件和动画属于模型/配置文件 UI 元数据或前端
  渲染器。 AI客户端可以传递元数据；它不应该定义
  产品体验。

## 请求合同

`defaults.ai.build_request` 产生消耗的标准化请求
§鲁米§0§：

```json
{
  "conversation_id": "c1",
  "model": "stub/default",
  "messages": [
    {"role": "system", "content": "profile-scoped prompt"},
    {"role": "user", "content": "hello"}
  ],
  "tools": [],
  "params": {}
}
```

调用者负责传递有效的系统提示并且已经
过滤工具。人工智能客户端应该将这些输入视为数据，而不是原因
读取或改变提示/工具存储。

## 模型简介

模型配置文件识别提供商特定的模型和功能，例如
愿景、工具调用、思维支持、上下文限制、路由提示。
当输入需要时，路由可能会推荐不同的模型配置文件
所选配置文件缺乏的功能。提供商密钥保留在配置文件之外
文件。

## 提供商发现

提供者发现是清单优先的。可以添加兼容 OpenAI 的提供商
与`extensions/llm/providers/<provider_id>/manifest.json`加上
§鲁米§0§；运行时从中实例化`OpenAICompatibleProvider`
配置凭据时会显示。自定义提供商协议仍可能
使用显式 Python 入口点。

精选的提供程序元数据是后备兼容性数据。它可能会填补遗产
显示名称或默认值，但清单和模型定义是规范的
新供应商的来源。

## 配置文件 UI 元数据

如果模型配置文件提供可选的 UI 元数据，例如`ui/events.ui.yaml`，则
流层可以将解析的小部件提示附加到标准化事件有效负载。
这是一个传递合约：

- 文件是可选的；
- 缺失的元数据必须保留现有的流媒体行为；
- 可以从当前事件数据解析模板；
- 前端渲染器决定是否使用或忽略小部件提示。

AI 客户端不得将“思考...”之类的硬编码动画作为提供者提供
逻辑。个人资料可以描述这些提示； AI客户端只携带它们。

## 失败行为

提供商错误应标准化为结构化错误结果，其中包括
提供商 ID、型号/配置文件 ID、已知时的可重试性以及用户安全
消息。丢失的凭据应该在网络调用之前关闭失败。不支持
功能应该被报告为功能错误而不是默默地丢弃
工具、图像或思维参数。
