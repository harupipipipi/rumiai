# Pack Development Quick Start Guide

> See [pack-development.md](./pack-development.md) for detailed API reference.

This guide explains the steps to create your first Pack using scaffold (a template generation tool), call it from Flow, and check its operation.

---

## Prerequisites

- Python 3.10 or higher
- Cloned environment of Rumi AI OS repository
- Working in the repository root (`rumi_ai_1_10/` directory must exist)

---

## Step 1: Generate Pack with template

`pack_scaffold` Generate a Pack template using CLI.

```bash
python -m core_runtime.pack_scaffold my_pack --template minimal --output ecosystem/
```

The following directory structure will be generated.

```
ecosystem/my_pack/
├── ecosystem.json
└── __init__.py
```

### Template type

| Template | Contents |
|-------------|------|
| `minimal` | Minimum configuration (`ecosystem.json` + `__init__.py`) |
| `capability` | minimal + `capability_handler.py` |
| `flow` | minimal + `flows/sample_flow.yaml` |
| `full` | All included (all of the above + `tests/` + `README.md`) |

### CLI options

| Options | Description |
|-----------|------|
| `--template`, `-t` | Template type (default: `minimal`) |
| `--output`, `-o` | Parent directory of output destination (default: current directory) |
| `--force`, `-f` | Allow overwriting of existing directories |

> If this is your first time, we recommend starting with the `minimal` template and adding files as needed.

---

## Step 2: Edit ecosystem.json

Edit `ecosystem.json` generated by scaffold. The scaffold output does not include `pack_identity`, so add it manually.

### ecosystem.json generated by scaffold

```json
{
  "pack_id": "my_pack",
  "version": "0.1.0",
  "description": "my_pack - A Rumi AI OS Pack",
  "capabilities": [],
  "flows": [],
  "connectivity": [],
  "trust": {
    "level": "sandboxed",
    "permissions": []
  }
}
```

### After editing (Added `pack_identity`)

```json
{
  "pack_id": "my_pack",
  "pack_identity": "github:your-username/my_pack",
  "version": "0.1.0",
  "description": "My first Rumi AI OS Pack",
  "capabilities": [],
  "flows": [],
  "connectivity": [],
  "trust": {
    "level": "sandboxed",
    "permissions": []
  }
}
```

### Required field

| Field | Description |
|-----------|------|
| `pack_id` | Pack identifier. Match directory name. Follow the pattern of `[a-zA-Z0-9_-]{1,64}` |
| `pack_identity` | Identifier indicating the distribution source (e.g. `github:author/repo`). If this value changes during Pack update, apply will be rejected |

> For details on each field, please refer to [the ecosystem.json section of pack-development.md](./pack-development.md#ecosystemjson).

## Step 3: Implement the block

The actual processing of Pack is written in blocks. Create the `backend/blocks/` directory and place the Python files there.

```
ecosystem/my_pack/
├── ecosystem.json
├── __init__.py
└── backend/
    └── blocks/
        └── hello.py
```

### Minimal block implementation

```python
# ecosystem/my_pack/backend/blocks/hello.py

def run(input_data, context=None):
    """
    Args:
        input_data: Flow から渡される入力データ（dict）
        context: 実行コンテキスト（dict）
    Returns:
        JSON 互換の dict
    """
    name = input_data.get("name", "World")
    return {"message": f"Hello, {name}!"}
```

### run() function signature

The `run()` function accepts one of the following three patterns.

```python
# パターン1: 入力データとコンテキストの両方（推奨）
def run(input_data: dict, context: dict) -> dict | None:
    ...

# パターン2: 入力データのみ
def run(input_data: dict) -> dict | None:
    ...

# パターン3: 引数なし
def run() -> dict | None:
    ...
```

### Important Notes

**Return value must be JSON compatible**: Return one of `dict`, `list`, `str`, `int`, `float`, `bool`, `None`.**Don't use keys with the `_` prefix**: If you include a key starting with the `_` prefix (e.g. `_internal`) in the returned dict, the Kernel will automatically exclude it.

```python
# NG: _ プレフィックスは除外される
def run(input_data, context=None):
    return {"_internal": "removed", "result": "kept"}
    # ctx に格納されるのは {"result": "kept"} のみ

# OK
def run(input_data, context=None):
    return {"result": "kept", "metadata": {"source": "my_pack"}}
```

**Validate input data**: Since `input_data` comes from an external source, be sure to perform type and existence checks.

```python
def run(input_data: dict, context: dict) -> dict:
    if not isinstance(input_data, dict):
        return {"error": "input_data must be a dict"}

    name = input_data.get("name")
    if not name or not isinstance(name, str):
        return {"error": "missing or invalid field: name"}

    return {"message": f"Hello, {name}!"}
```

> For detailed block specifications, please refer to [the blocks section of pack-development.md](./pack-development.md#blocks).

## Step 4: Validation

Verify that the Pack settings are correct using the validation tool.

```bash
python app.py --validate
```

Validation checks the following:

| Check items | Explanation |
|-------------|------|
| JSON parse | Is `ecosystem.json` valid JSON? |
| `pack_id` Match | Does the directory name match `pack_id` in `ecosystem.json` |
| `connectivity` Declaration | `connectivity` Is the field declared |
| `${ctx.*}` Referential integrity | Are `${ctx.PACK_ID.*}` references in the Flow contained in `connectivity` |

### Verification from program

```python
from core_runtime.pack_validator import validate_packs

report = validate_packs(ecosystem_dir="ecosystem/")
print(f"Pack 数: {report.pack_count}, 有効: {report.valid_count}")

for w in report.warnings:
    print(f"  WARNING: {w}")
for e in report.errors:
    print(f"  ERROR: {e}")
```

## Step 5: Test

### Manual testing

You can run the Flow directly to see the block in action. Create a test Flow file in `user_data/shared/flows/`.

```yaml
# user_data/shared/flows/test_hello.flow.yaml

flow_id: test_hello
inputs:
  name: string
outputs:
  greeting: object

phases:
  - main

steps:
  - id: call_hello
    phase: main
    priority: 50
    type: python_file_call
    owner_pack: my_pack
    file: blocks/hello.py
    input:
      name: "Alice"
    output: greeting
```

### Unit testing from Python

The block's `run()` function is a simple Python function that you can call and test directly.

```python
# tests/test_hello.py

import sys
sys.path.insert(0, "ecosystem/my_pack/backend")

from blocks.hello import run

def test_hello_basic():
    result = run({"name": "Alice"})
    assert result == {"message": "Hello, Alice!"}

def test_hello_default():
    result = run({})
    assert result == {"message": "Hello, World!"}
```

## Step 6: Call from Flow

Pack blocks are called from the Flow definition.

### Flow file placement

| Path | Purpose |
|------|------|
| `user_data/shared/flows/` | Share Flow. Used for wiring across multiple packs |
| `ecosystem/<pack_id>/backend/flows/` | Pack-specific Flow |

### Flow definition example

```yaml
# user_data/shared/flows/greet.flow.yaml

flow_id: greet
inputs:
  name: string
outputs:
  greeting: object

phases:
  - main

steps:
  - id: call_hello
    phase: main
    priority: 50
    type: python_file_call
    owner_pack: my_pack
    file: blocks/hello.py
    input:
      name: "${ctx.name}"
    output: greeting
```

### Key fields for steps

| Field | Required | Description |
|-----------|------|------|
| `id` | ✅ | Step ID (unique within the Flow) |
| `phase` | ✅ | Affiliation phase |
| `priority` | Optional | Execution priority (ascending order; default 100) |
| `type` | ✅ | `python_file_call` |
| `owner_pack` | Optional | Owned Pack ID |
| `file` | ✅ | Relative path of executable file |
| `input` | Optional | Input data (variable expansion possible with `${ctx.key}`) |
| `output` | Optional | Output destination context key |
| `timeout_seconds` | Optional | Timeout seconds (default 60, maximum 120) |

### Variable expansion

You can reference the value in context with `${ctx.key}`. Nested references (`${ctx.user.id}`) are also possible. If the reference does not exist, it will be `null`.

> For details on Flow definition, please refer to [Flow definition section of pack-development.md](./pack-development.md#flow-definition).

## Utilization of foundation modules

The core runtime of Rumi AI OS provides the foundation modules commonly required for Pack development. Below we will introduce the basic usage of each module.

### Structured log

The `core_runtime.logging_utils` module supports structured log output in JSON format.

```python
from core_runtime.logging_utils import get_structured_logger, CorrelationContext

logger = get_structured_logger("rumi.pack.my_pack")

def run(input_data, context=None):
    logger.info("Processing request", pack_id="my_pack", flow_id=context.get("flow_id"))

    # correlation_id でリクエスト追跡
    with CorrelationContext(correlation_id=context.get("flow_id", "unknown")):
        logger.info("Step started")
        # ... 処理 ...
        logger.info("Step completed")

    return {"status": "ok"}
```

`get_structured_logger()` is a cached factory function that returns identical instances for the same name. You can create a logger with a fixed common context using the `bind()` method.

```python
ctx_logger = logger.bind(pack_id="my_pack", flow_id="main_flow")
ctx_logger.info("Step 1")  # pack_id, flow_id が自動付与
ctx_logger.info("Step 2")  # pack_id, flow_id が自動付与
```

The output format can be controlled with the environment variable `RUMI_LOG_FORMAT` (`json` or `text`).

> See [the structured log settings section of operations.md](./operations.md#structured-log-settings) for details.

### Unified error

The `core_runtime.error_messages` module provides a uniform error coding scheme (`RUMI-{CATEGORY}-{NUMBER}`).

```python
from core_runtime.error_messages import format_error, RumiError
from core_runtime.error_messages import VAL_EMPTY_VALUE, PACK_ID_INVALID

def run(input_data, context=None):
    name = input_data.get("name")
    if not name:
        raise format_error(VAL_EMPTY_VALUE, field_name="name")
        # => RumiError: RUMI-VAL-001: name must not be empty

    return {"message": f"Hello, {name}!"}
```

`format_error()` embeds parameters in the `ErrorCode` constant template and returns a `RumiError` instance. `RumiError` has `.code`, `.message`, `.suggestion`, `.details` attributes and can be converted to a JSON serializable dict with `.to_dict()`.

Main error code categories: `AUTH` (Authentication), `NET` (Network), `FLOW` (Flow), `PACK` (Pack Management), `CAP` (Capability), `VAL` (Validation), `SYS` (System).

> See [the error code reference section of operations.md](./operations.md#error-code-reference) for details.

### Type annotations

The `core_runtime.types` module provides `NewType` for specifying the use of ID strings at the type level.

```python
from core_runtime.types import PackId, FlowId, JsonDict, Result

def process_pack(pack_id: PackId, flow_id: FlowId) -> JsonDict:
    return {"pack_id": pack_id, "flow_id": flow_id}

# Result[T] で成功/失敗を表現
def load_data(key: str) -> Result[JsonDict]:
    try:
        data = fetch(key)
        return Result(success=True, value=data)
    except Exception as e:
        return Result(success=False, error=str(e))
```

Available types: `PackId`, `FlowId`, `CapabilityName`, `HandlerKey`, `StoreKey` (NewType), `JsonValue`, `JsonDict` (type alias), `Result[T]` (generic result type), `Severity` (log severity enumeration type).

> For details, see [the type hints/validation section of pack-development.md](./pack-development.md#type-hintsvalidation).

### Deprecated API Management

The `deprecated` decorator in the `core_runtime.deprecation` module allows you to manage deprecated APIs systematically.

```python
from core_runtime.deprecation import deprecated

@deprecated(since="1.0", removed_in="2.0", alternative="new_handler")
def old_handler(input_data, context=None):
    """この関数は非推奨です。"""
    return new_handler(input_data, context)
```

When a decorator is given, `DeprecationWarning` is issued when the function is called, and it is automatically registered in `DeprecationRegistry`. `async def` is also supported.

The warning behavior can be controlled with the environment variable `RUMI_DEPRECATION_LEVEL` (`warn` / `error` / `silent` / `log`).

> See [the deprecation warning level control section of operations.md](./operations.md#deprecation-warning-level-control) for details.
