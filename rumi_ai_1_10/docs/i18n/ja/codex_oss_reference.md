# Codex OSS リファレンス ノート

OpenAI Codex OSS は、Rumi のコーディング ツール サーフェスのリファレンスとしてレビューされました。
有用な部分は主にアーキテクチャやワークフロー指向であり、
Rumi はローカルファーストの Python パック ランタイムであるため、コードを直接ポートします。
Codex は Rust ターミナル コーディング エージェントであるのに対し、承認モデルです。

## このリポジトリで採用されました

- エージェント ローカル リポジトリの命令は、ルート `AGENTS.md` にキャプチャされます。
  これは、コーディング エージェントの規約を明示的にする Codex のパターンに従っています。
  ソースツリーに近い。
- 共通の開発コマンドはルート`justfile`にグループ化されており、ミラーリングされています
  Codex のテスト、リンティング、集中的なワークフローのための単一コマンド エントリポイント。
- プロバイダー ツールのスキーマは、モデル プロバイダーに送信される前に正規化されます。
  アダプターは、不正な形式または従来の JSON スキーマ フラグメントを、
  プロバイダーセーフなサブセット、到達不能なローカル定義を削除し、使用可能なものを保持します
  refs を使用すると、非常に大規模なスキーマが圧縮され、ツール登録の復元力が維持されます。
- ターミナルコマンドのリスク分類は、一般的な読み取り専用検出を認識します
  `rg`、`git ls-files`、`ruff check`、および
  `cargo check` はシェルエスケープとワークスペース外を維持しながらリスクが低い
  小切手。

## このパスの前にすでに存在しています

- 承認対応ファイル、ターミナル、git、GitHub 読み取り、およびワークスペース API。
- 機密性の高いコーディング操作用の署名付きサーバー側承認トークン。
- ワークスペースルートの制限と登録された信頼できるワークスペースのチェック。
- Codex スタイルのアプリサーバー バックエンド スキャフォールド
  `ecosystem/defaultspack/domain/coding_backends/codex-app-server/`。
- 静的、セキュリティ、パッケージ、フロントエンド、Rust、Windows、およびインストーラー CI レーン。
- ツールの検出、推奨、ポリシーのフィルタリング、およびモデルプロバイダー
  適応。

## 直接移植されていません

- Codex の Rust クレート分割、Bazel/RBE リリース パイプライン、TUI スナップショット
  ワークフローは移植されません。 Rumi の境界はパック、Python ランタイムです
  モジュール、Tauri ビューア クレート、Web アプリ テスト。
- Codex 固有のリリース パッケージ、コード署名、古い PR の自動化、
  CLA ワークフローは、このリポジトリの現在のライフサイクルに明確にマッピングされていません。
- Codex のホストされたツール/プラグインのインストール フローは、Rumi では次のように表されます。
  defaultspack コンポーネント マニフェスト、関数マニフェスト、および機能ポリシー
  1 対 1 のコネクタ インストーラーではなく。

## 将来の候補者

- 生成された大規模なアセットが着陸し始めた場合は、ブロブサイズの非回帰ゲートを追加します
  意図せずPRに。
- テキスト DOM が使用される高密度 UI パネルにスナップショット スタイルのフロントエンド カバレッジを追加します。
  テストでは視覚的な回帰が見逃されます。
- Rumi が完了したら、codex-app-server バックエンド スキャフォールドを試験運用から昇格させます。
  実際の双方向アプリサーバートランスポート。
