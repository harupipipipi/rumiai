# 默认包 v2

> **旧备忘录**：这是一份旧备忘录，只有摘要。有关当前解释，请参阅[defaultspack-v2.md](./defaultspack-v2.md)。

`defaultspack` 现在是`ecosystem/defaultspack/` 下的可追踪的一流包。

## 发生了什么变化

- 规范后端 API 路径现在位于 `/api/defaultspack/*` 下。
- 安装包发现来自`ecosystem/setup_pack/*/pack.json`。
- 模块状态由 defaultspack 后端模块助手进行编目和保存。
- Defaultspack 操作通过`functions/`执行，而不是直接块导入。
- 包修改请求现在在批准之前强制执行插槽/全屏冲突规则。
- 旧版 CLI/HTTP 回退通过 `bridge/block_adapter.py` 传输调度，而不是直接导入块处理程序。

## 设置流程

`/setup` 下的安装 UI 会询问是否应在启动时包含发现的安装包。
选定的安装包会一起安装，并从安装程序中获得`all OK`资助。

`supports_all_ok` 是存储库管理的可信安装包元数据，位于
§鲁米§0§。上游仅处理经过维护者审查的安装包
定义为可信的。叉子可能会添加自己的安装包，但这样做是
与修改该分叉中的可信源相同；它不是一个单独的运行时
脆弱性边界。

## 包修改流程

可以先暂存包更改，然后按以下任一方式提交：

- §鲁米§0§
- §鲁米§0§

两者都会在任何申请发生之前生成受批准支持的请求记录。

冲突政策：

- 全屏请求在活动的待处理/已应用的请求中是独占的
- 独占请求不能共享同一个槽
- 保留非独占的同槽前端请求，但标记为显式主动选择
