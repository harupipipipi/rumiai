# 코덱스 OSS 참고사항

OpenAI Codex OSS는 Rumi의 코딩 도구 표면에 대한 참조로 검토되었습니다.
유용한 부분은 대부분 아키텍처 및 워크플로 지향적입니다.
Rumi는 로컬 우선 기능을 갖춘 Python 팩 런타임이기 때문에 직접 코드 포트를 사용합니다.
Codex는 Rust 터미널 코딩 에이전트인 반면 승인 모델입니다.

## 이 저장소에 채택됨

- 에이전트-로컬 저장소 지침은 루트 `AGENTS.md`에 캡처됩니다.
  이는 코딩 에이전트 규칙을 명시적이고 명확하게 만드는 Codex의 패턴을 따릅니다.
  소스 트리에 가깝습니다.
- 일반적인 개발 명령은 루트 `justfile`에 그룹화되어 미러링됩니다.
  테스트, Linting 및 집중적인 워크플로를 위한 Codex의 단일 명령 진입점입니다.
- 제공자 도구 스키마는 모델 제공자에게 전송되기 전에 정규화됩니다.
  이제 어댑터는 잘못된 형식이나 레거시 JSON 스키마 조각을
  공급자 안전 하위 집합, 도달할 수 없는 로컬 정의 제거, 사용 가능한 상태 유지
  refs는 매우 큰 스키마를 압축하고 도구 등록 탄력성을 유지합니다.
- 터미널 명령 위험 분류는 일반적인 읽기 전용 검색을 인식합니다.
  `rg`, `git ls-files`, `ruff check`와 같은 테스트 명령 및
  `cargo check`는 쉘 탈출 및 외부 작업 공간을 유지하면서 위험이 낮습니다.
  수표.

## 이 패스 이전에 이미 존재함

- 승인 인식 파일, 터미널, git, GitHub 읽기 및 작업 공간 API.
- 민감한 코딩 작업을 위해 서명된 서버측 승인 토큰입니다.
- 작업공간 루트 제한 및 등록된 신뢰할 수 있는 작업공간 확인.
- Codex 스타일 앱 서버 백엔드 스캐폴드
  §루미§0§.
- 정적, 보안, 패키지, 프런트엔드, Rust, Windows 및 설치 프로그램 CI 레인.
- 도구 검색, 추천, 정책 필터링 및 모델 제공자
  적응.

## 직접 포팅되지 않음

- Codex의 Rust 크레이트 분할, Bazel/RBE 릴리스 파이프라인 및 TUI 스냅샷
  워크플로우는 이식되지 않습니다. Rumi의 경계는 팩, Python 런타임입니다.
  모듈, Tauri 뷰어 상자 및 웹앱 테스트.
- Codex 관련 릴리스 패키징, 코드 서명, 오래된 PR 자동화 및
  CLA 워크플로는 이 저장소의 현재 수명 주기에 명확하게 매핑되지 않습니다.
- Codex의 호스팅 도구/플러그인 설치 흐름은 Rumi에서 다음과 같이 표현됩니다.
  defaultspack 구성 요소 매니페스트, 함수 매니페스트 및 기능 정책
  일대일 커넥터 설치 프로그램이 아닌

## 미래 후보

- 대규모로 생성된 자산이 착륙하기 시작하면 blob 크기 비회귀 게이트를 추가합니다.
  의도치 않게 PR에
- 텍스트 DOM이 있는 밀집된 UI 패널에 스냅샷 스타일 프런트엔드 적용 범위를 추가합니다.
  테스트에서 시각적 회귀가 누락되었습니다.
- Rumi가 일단 실험에서 codex-app-server 백엔드 스캐폴드를 승격합니다.
  실제 양방향 앱 서버 전송.
